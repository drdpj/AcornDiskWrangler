## Acorn Disk Wrangler 1.6.0

BBC Micro and Electron cassette tapes, read and written. It uses the DiskWranglerCore library version 1.4.1.

### New
- **Cassette tapes.** BBC Micro and Electron tape images (UEF files, compressed or not) open in a window of their
  own, with one tab, **Tape**: the files in the order they are on the tape, with their load and exec addresses,
  length, number of blocks, **P** for a protected file and any problem (a bad CRC, a missing block). Two files may
  share a name; both show it.
- **Copying off a tape.** Drag files onto an ADFS or DFS disc or out to the computer, or use Copy and Paste or
  Extract, as from a disc: load and exec go with them (a disc copy drops the protected flag), and two files of the
  same name both arrive (`GAME` and `GAME (2)`, each `.inf` saying `GAME`).
- **Writing tapes.** Files dropped on a tape (from the computer, a disc or another tape), Add files and Paste go on
  its end, saved as the BBC Micro's MOS saves them (its leader, its gaps between blocks, 256-byte blocks). Drag rows up
  and down to change the order (`CHAIN ""` loads the next file on the tape). Rename, Properties (load, exec,
  protected) and Delete work as on a disc, changing only that file on the tape. Save writes the tape back as it came
  (compressed or not); Save As offers both. **File > New disc image** makes an empty tape (Tape (UEF)).
- **Data the tape's own loader wrote** in a format of its own is shown as *unrecognised data* and kept as it is, as
  are files with problems. Dragged to another tape they go on its end exactly as they were, errors and all, so a
  game with its own loader can be copied tape to tape and still loads; dragged anywhere else they become files of
  their bytes, to look at.
- Tapes written by the program were checked by loading them on a BBC Micro's MOS 1.20 in an emulator (jsbeeb), and
  files the MOS saved read back byte for byte.
- **`acorndw`** reads and writes tapes: `info`, `ls`, `get`, `put`, `copy`, `rm`, `mv`, `attr` and
  `new --format=uef`; `#3` names the third file on the tape.

### Changed
- **`.inf` files**: a name with a `.` that isn't a DFS directory letter (a tape file's `V1.0`) is read whole when the
  `.inf` quotes it (as Extract now writes such a name) or it is the host file's own name; before, only the part after
  the last dot was taken (`0`).

### Known limits
- Tapes recorded as sound (WAV, CSW) and the Acorn Atom's aren't read; ZX Spectrum and Amstrad CPC tapes (TZX, CDT,
  TAP) are named, not opened.
- The Electron's OS hasn't been checked against the BBC's (the Electron tapes tried read the same). Tapes written
  here were checked in an emulator, not on a real cassette recorder.
- `acorndw` has no command to change the order of a tape's files (the window does it).
- Watford's double-density DDFS, ADFS new-map discs (D and E) and copy-protected discs aren't supported.
- TeleDisk images can't be saved as TeleDisk (Save As writes another kind).
- Discs written by this program have been checked against Watford's ROM code, but not yet read by it on a real
  machine.
- A new DOS Plus 640K disc hasn't yet been tried on a real Master 512.
- None of the builds is signed: Windows and macOS warn the first time (see the README).

### Building from source
The shared code is the DiskWranglerCore library (version 1.4.1), a git submodule in `core/`. Clone with
`git clone --recurse-submodules`, or run `git submodule update --init` after cloning. GitHub's "Download ZIP" and
"Source code" archives leave `core/` empty; use the complete source archive attached to this release.

### Downloads
Windows installer and zip, macOS disk image, Linux AppImage and .deb, each for Qt 6, with `acorndw` in each; and
the complete source (`...-source.tar.gz`, with `core/`).
